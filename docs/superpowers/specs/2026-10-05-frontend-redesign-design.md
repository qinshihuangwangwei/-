# 前端重构设计 · 台账

2026-10-05　·　方向 A（台账），已在三方向样张中选定

**范围**：视觉重做（设计令牌 + 组件词汇）＋ 顶部横向导航改为侧边栏 ＋ 界面文案清理
　　　　　＋ 暗色与打印支持。
**不在本轮**：表格排序／筛选／明细折叠等交互增强（见 §10.1，下一轮接上）。

---

## 1. 这次重构要解决什么

原话是「前端太丑了」。但把它当成配色问题会做错方向 —— 盘一遍现状之后，
真正的问题是三个，而且第三个最要紧。

### 1.1 现状盘点

| | |
|---|---|
| 页面数 | **26 个**渲染函数 |
| 渲染代码 | `src/http/views.ts` 2534 行 + `src/ui/publicity.ts` 383 行 |
| 全部 CSS | **135 行**（`views.ts` 86 + `publicity.ts` 49） |
| HTML 元素 | 123 个 `<td>`、105 个 `<th>`、34 张表、39 个表单、39 个按钮 |

**135 行 CSS 服务 26 个页面** —— 这是"丑"的直接原因：没有组件词汇，
每个页面都在用浏览器默认样式。

### 1.2 两份互不相干的样式表

公示页（`publicity.ts`）自带一套 `STYLE`，主界面（`views.ts`）另有一套。
于是**产品唯一面向全院的那个界面，和产品其他部分长得不像一个东西**。

### 1.3 顶部横向导航已经到了上限

实测每个角色的导航项数：

| 角色 | 项数 | 内容 |
|---|---|---|
| 普通学生 / 干事 | 4 | 首页 我的 我的录入 公示页 |
| 部长 | 5 | ＋本部门 |
| 主席 | 7 | ＋全院 责任指派 部长任命 异议裁决 |
| **管理员** | **11** | ＋管理 主席任命 管理员 账号 |

**11 项横着排会换行**，而且全部平铺 —— "首页"和"任命管理员"视觉权重完全一样。
角色越重的人、越需要频繁跳转的人，导航越难用。

### 1.4 界面在向维护者解释自己（最要紧的一条）

文案审计挖出**成段的设计理由**直接印在页面上：

> 「未指派即禁止录入 —— 默认归某个部门，就等于把没人认领的活静默变成某人的责任。」
> 「别把它们合并成一句「未提交」：一个刚提交完的人回来看见「未提交」，
> 　只会以为系统把他的提交吞了。」
> 「同一个人身兼两职，他一个人就能凑齐两组签署 —— 双签就退化成了一个人签两次。」
> 「下载目录里旧的同名文件很容易和新的混起来 —— 对一下文件名里的时间就不会。」
> 「主席也是学生，不该拿到这样一张表。」
> 「第一个管理员用服务器上的 `npm run admin:init` 创建。」

这些段落**不是多余的**——它们每一段都在补一个界面没能表达出来的区别。
但它们写给的对象错了：那是设计说明，读者是维护者，不是录分的部长。

**所以这次重构的主轴不是"删文案"，而是：**

> **把解释变成界面。** 状态用形状区分、上限用刻度显示、流程用进度呈现 ——
> 界面对了，话自然就不需要了。

## 2. 设计方向：台账

这个产品真正特别的地方不是"又一个成绩表"，而是**一本只增不改的账**：
每一分都有时间、有经手人、有理由、有哈希链，可以被逐条追问。

那就照着账册来做。不是比喻，是直接借用它的形制：

| 账册的形制 | 在界面上对应什么 |
|---|---|
| 纸与墨 | 冷调纸面 + 蓝黑墨色文字 |
| 界格线 | 1px 细线，不用斑马纹、不用阴影 |
| 红笔 | **印泥红只用于存证与危险动作**，不做装饰 |
| 合计双线 | `tfoot` 上方 `border-top: 3px double` |
| 凭证 | 每一笔加分是账上的一节，挂在一条可追溯的链上 |

**签名元素是「凭证链」（`.rail`）**：一个人的每一笔加分沿着一条竖线排列，
每节挂着「谁录的 / 谁复核的 / 谁批的 / 什么时候 / 什么理由」。
它把"这是可以逐条追问的账"这件事直接画了出来 —— 而不是用一句话说出来。

这是这次唯一一处承担"记忆点"职责的元素，其余全部保持安静。

## 3. 设计令牌

### 3.1 颜色

**亮色为主**（`--paper` 一套）：

| 令牌 | 值 | 用途 |
|---|---|---|
| `--paper` | `#F6F5F1` | 纸面。**冷调灰绿**，刻意避开 AI 惯用的暖米色 `#F4F1EA` |
| `--surface` | `#FFFFFF` | 卡片、表格底色 |
| `--ink` | `#1B2430` | 正文（蓝黑墨） |
| `--ink-soft` | `#5C6672` | 次要文字、表头标签 |
| `--rule` | `#DCDAD2` | 界格线 |
| `--rule-soft` | `#E9E7DF` | 行分隔线 |
| `--seal` | `#A83A32` | **印泥红。只用于存证印与危险动作** |
| `--check` | `#2C6E4F` | 已统计、已批准、正向 |
| `--warn` | `#8A5A12` | 未提交、未指派 |
| `--info` | `#1F4E79` | 录入中、进行中 |

**四种状态色 + 中性**，符合"状态不超过 5 种"的经验值。

**印泥红与错误色分开**：错误不用红色表达，用**边框 + 位置 + 文案**表达
（`.note.err` 一条左侧粗边）。红在这个系统里的含义是"印章"，
让它同时表示"出错了"会两头都不清楚。

### 3.2 字体

全部使用系统字体，**零依赖**（这个项目没有构建步骤，不能引入 Web Font）。

| 角色 | 字体栈 | 用在哪 |
|---|---|---|
| 标题 | `"Songti SC", "SimSun", "Noto Serif CJK SC", Georgia, serif` | **仅 h1 / h2** |
| 正文 | `system-ui, "PingFang SC", "Microsoft YaHei", sans-serif` | 其余全部 |
| 数字 | `ui-monospace, "Cascadia Mono", Consolas, "SF Mono", monospace` | 分数、学号、时刻、哈希 |

字号阶：`1.5 / 1.15 / 1.0 / 0.87 / 0.78 rem`。
所有数字加 `font-variant-numeric: tabular-nums`，**数字列一律右对齐**。

宋体只出现在标题上。这是刻意的克制：公文的端庄来自"少量且固定"，
一旦正文也用宋体，小字号下可读性会明显下降。

### 3.3 形

- **圆角最大 `2px`**。账册是直角的；现在满屏的 999px 胶囊按钮和 8px 卡片边角
  是"通用 SaaS"的味道，和这个产品的气质相冲。
- 间距基数 4px：`.25 / .5 / .75 / 1 / 1.5 / 2 / 3 rem`
- 不用阴影（`box-shadow`）分层，用**线与留白**分层
- 合计行：`tfoot td { border-top: 3px double var(--ink) }`

## 4. 组件词汇表

### 4.1 与测试的契约（先定这个，因为它决定改动风险）

盘过全部测试文件，**只有 7 个 class 名被断言**：

```
.baseline   .task（.entry / .review / .approve 三种）   .badge
.flash.toast   .topbar   .who-name   .who-meta
```

外加一批 `data-*` 属性钩子（`data-student` / `data-event` / `data-item`）。

**这 10 个钩子保持原样，其余 class 可以自由增删改名。**
于是"保持功能不变"不是一句承诺，而是**重构后跑一遍全量测试就能证明的事实**。

`.task.entry / .task.review / .task.approve` 恰好就是"录入 / 复核 / 批准"三块，
语义本来就对，直接沿用，只重做它们的样子。

### 4.2 新增词汇

| 类 | 职责 |
|---|---|
| `.sheet` | 页面主容器。统一 26 个页面各自为政的内边距与最大宽度 |
| `.pagehead` | 标题 + 副标题 + 右侧存证印 |
| `.seal` | 存证徽章：账本校验通过 / 切片已冻结。**唯一使用印泥红的地方之一** |
| `.tbl` | 数据表。表头吸顶、数字列右对齐、可选 `tfoot` 双线合计 |
| `.num` | 等宽 + `tabular-nums` |
| `.tag` → `.tag-done` `.tag-zero` `.tag-none` `.tag-doing` | **四态四形**状态徽章 |
| `.rail` | 凭证链（签名元素） |
| `.steps` | 三段流转进度：提交 → 复核 → 批准 |
| `.field` + `.meter` | 表单字段组 + 上限刻度条 |
| `.note` / `.note.err` | 内联提示与错误（取代长篇解释） |
| `.empty` | 空状态：一句引导 + 一个动作 |
| `.flash` | 顶部提示条（已有，保留） |

### 4.3 四态四形 —— 把那段解释变成界面

现在"已统计 · 0 条"和"未提交"都是灰色文字，只能靠一段话区分。

改成 **填充／空心 × 色相** 的二维区分：

| 状态 | 填充 | 色相 | 读作 |
|---|---|---|---|
| 已统计（有条数） | **实心** | 校色 `--check` | 做完了，账上有记录 |
| 已统计 · 0 条 | **空心** | 中性灰 `--ink-soft` | 查过了，确实没有人加分 |
| 未提交 | **实心** | 警示 `--warn` | 该有人做，但没人做 —— 需要动作 |
| 录入中 | **空心** | 信息蓝 `--info` | 正在做 |

填充这一维本身就有含义：**实心 = 已经落地（做完了／出问题了），空心 = 还在悬着**。
于是即使完全看不见颜色（色觉差异、黑白打印、低对比度屏幕），
四个状态仍然两两可分 —— 色相只是加强，不是唯一依据。

页面上只留一行图例，那段解释删掉。

## 6. 侧边栏

### 6.1 为什么是侧边栏

1.3 那张表就是理由：管理员的导航有 11 项，横向排不下，而且**平铺意味着没有层级**。
侧边栏能同时解决两件事 —— 放得下，并且能分组。

另一个好处是**竖向空间**。横向导航占掉顶部一整条，加上页头，
数据表在 1366×768 的笔记本上只剩不到 600px —— 而这是个表格密集的应用。

### 6.2 结构

```
┌────────────┬──────────────────────────────────┐
│ 综测计分     │  页头：标题 · 身份 · 退出 · 主题  │
│            ├──────────────────────────────────┤
│ 我的         │                                  │
│  首页        │                                  │
│  我的        │         主内容（.sheet）          │
│  我的录入     │                                  │
│            │                                  │
│ 全院         │                                  │
│  全院看板     │                                  │
│  责任指派     │                                  │
│  ⋯          │                                  │
│            │                                  │
│ 管理         │                                  │
│  管理        │                                  │
│  ⋯          │                                  │
│            │                                  │
│ 公示页        │                                  │
└────────────┴──────────────────────────────────┘
```

分组按角色裁剪：没有的组不出现，管理员看到三组，普通学生只看到「我的」一组加公示页。

### 6.3 折叠

- 展开态 13rem；折叠态 3.5rem（窄轨）
- **折叠后每项显示标签首字**（「首」「我」「录」「院」「派」「命」「裁」「管」「席」「员」「账」「示」）。
  中文标签天然适合这么压 —— 不需要图标字体，不需要任何依赖
- 状态写 `localStorage`，刷新后保持
- **窄屏（< 900px）自动折叠**，用媒体查询；手动展开仍然可用
- 折叠按钮在侧边栏底部，不占页头

### 6.4 与测试的契约

`ui-reachability.test.ts` 里有两条断言依赖导航结构：

```ts
const navOf = (html) => /<nav>([\s\S]*?)<\/nav>/.exec(html)?.[1] ?? "";
assert.ok(!navOf(page).includes("/logout"), ...);   // 退出在页头，不在导航里
```

**保留 `<nav>` 元素**（放进 `<aside>` 里即可），这两条断言继续成立。
`navFor()` 的返回值结构不变，只是多加一层分组信息。

## 7. 暗色与打印

### 7.1 暗色（可选）

- **默认跟随系统**：`@media (prefers-color-scheme: dark)` 只覆盖颜色令牌，其余不变
- **手动开关**：页头一个按钮，写 `localStorage`，在 `<html>` 上设 `data-theme`。
  约 15 行内联脚本，无依赖
- 无 JS 时退化为跟随系统 —— 开关是增强，不是前提

### 7.2 打印

公示页是要"贴出来"的东西，必须有打印样式：

```css
@media print {
  aside, header, .topbar, .flash { display: none }
  body { background: #fff; color: #000 }
  thead { display: table-header-group }   /* 每页重复表头 */
  tr { break-inside: avoid }              /* 行不被截断 */
  .rail, .rail li { break-inside: avoid }
}
```

打印时侧边栏一并隐藏 —— 纸上不需要导航。

## 8. 迁移步骤

1. **新建 `src/ui/theme.ts`**：一份 `THEME_CSS`（令牌 + 组件词汇 + 暗色 + 打印）。
   `views.ts` 与 `publicity.ts` 的**两份 `STYLE` 合并成这一份** —— 顺手修掉 1.2 那条不一致。
2. **`layout()` 与公示页引用同一个 `THEME_CSS`**。
3. **`layout()` 改成「侧边栏 + 内容区」的栅格**，`navFor()` 加分组。
4. **26 个页面逐页换 class 与结构**，保住第 4.1 节的 10 个钩子。
5. **文案清理**（第 5 节）。
6. **暗色开关**接进页头。

改动顺序按"从共用构件到具体页面"：先 `.sheet` / `.tbl` / `.tag` 这些被反复用到的东西，
再逐页收口。这样第 4 步做了一半时，页面也不会比原来更难看。

侧边栏（第 3 步）做了之后**所有 26 个页面同时受益**，所以它排在逐页改之前。

## 10. 这一轮不做的事

### 10.1 交互增强 —— 下一轮，不是不做

排序、筛选、明细折叠都值得做，而且都能用原生 JS 以"渐进增强"的方式加
（服务端照旧渲染整页，JS 只是加速器；无 JS 时 26 个页面全部可用）。

**这一轮先不做，是因为要和侧边栏分开验证**：视觉、导航、交互三件事同时改，
出问题时分不清是谁造成的。设计已经记在这里，下一轮直接接上。

### 10.2 明确不做

- **不做路由式 SPA。** 公示页必须"打开就能看、不需要登录也能存证"——
  一个纯客户端应用会让它变成必须先加载 JS 才能读的东西，
  而这一页的职责恰恰是**存证**。另外这个项目零依赖零构建，
  换 SPA 等于另开一个项目。
- **不引入任何依赖**。没有 Tailwind、没有组件库、没有图标字体、没有 Web Font。
- **不动任何行为**：权限、状态机、跳转、表单字段名、`data-*` 钩子全部不变。
- **不动账本相关的任何逻辑**：这一轮只碰渲染层。
